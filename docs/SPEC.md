# IOCL Prep Hub — Product Specification

Status: proposed for approval  
Target exam: IOCL Graduate Engineer, Grade A — Computer Science and Information Technology  
Tentative CBT date: 24 September 2026

## 1. Product purpose

IOCL Prep Hub is a local, focused study and practice tool for one candidate preparing for the 2026 IOCL Computer Science and IT CBT. It must help the candidate:

- practise the exact notified CBT section structure and negative marking;
- concentrate on Computer Networks, Theory of Computation, and timed quantitative aptitude;
- distinguish knowledge from lucky guesses by recording confidence before revealing the answer;
- review mistakes and low-confidence correct answers;
- see trustworthy progress by subject and topic.

This is an exam tool, not a portfolio project. Correct content, fast practice, readable review, and dependable local data take priority over visual novelty.

- All questions are objective multiple-choice questions.
- Each question carries 1 mark.
- Each incorrect answer deducts 0.25 mark.

- IOCL may normalize scores if the CBT is held in more than one session.

## 3. Syllabus

The IOCL documents define the authoritative broad scope. The official GATE 2026 CS syllabus is used only to expand IOCL’s ten broad domain headings into study topics. Historical GATE papers do not define or widen the IOCL syllabus.

### 3.1 General Aptitude — official IOCL detail

#### Quantitative Aptitude

- Data interpretation: bar graphs, pie charts, other data graphs, 2D and 3D plots, maps, and tables
- Numerical computation and estimation: ratios, percentages, powers, exponents, logarithms, permutations and combinations, and series
- Mensuration and geometry
- Elementary statistics and probability

#### Logical Reasoning

- Deduction and induction
- Analogy
- Numerical relations and reasoning
- Shape transformations: translation, rotation, scaling, and mirroring
- Assembling and grouping
- Paper folding and cutting
- Patterns in two and three dimensions

#### Verbal Ability of English Language

- Basic grammar: tenses, prepositions, articles, adjectives, conjunctions, verb–noun agreement, and other parts of speech
- Vocabulary, idioms, and phrases in context
- Reading comprehension
- Narrative sequencing

Source: `IOCL-GA-SYL-2026`, pages 1–3.

### 3.2 Domain Knowledge — IOCL headings expanded only by official GATE CS 2026

#### 1. Engineering Mathematics

- Discrete mathematics: propositional and first-order logic; sets, relations, functions; partial orders and lattices; monoids and groups; graph connectivity, matching, and colouring; counting, recurrence relations, and generating functions
- Linear algebra: matrices, determinants, systems of linear equations, eigenvalues and eigenvectors, and LU decomposition
- Calculus: limits, continuity, differentiability, maxima and minima, mean value theorem, and integration
- Probability and statistics: random variables; uniform, normal, exponential, Poisson, and binomial distributions; mean, median, mode, and standard deviation; conditional probability and Bayes theorem

#### 2. Digital Logic

- Boolean algebra
- Combinational and sequential circuits
- Minimization
- Number representations
- Fixed- and floating-point computer arithmetic

#### 3. Computer Organization and Architecture

- Machine instructions and addressing modes
- ALU, datapath, and control unit
- Instruction pipelining and pipeline hazards
- Memory hierarchy: cache, main memory, and secondary storage
- I/O interface, interrupts, and DMA

#### 4. Programming and Data Structures

- Programming in C
- Recursion
- Arrays, stacks, queues, linked lists, trees, binary search trees, binary heaps, and graphs

#### 5. Algorithms

- Searching, sorting, and hashing
- Asymptotic worst-case time and space complexity
- Greedy, dynamic programming, and divide-and-conquer techniques
- Graph traversals, minimum spanning trees, and shortest paths

#### 6. Theory of Computation

- Regular expressions and finite automata
- Context-free grammars and push-down automata
- Regular and context-free languages
- Pumping lemma
- Turing machines and undecidability

#### 7. Compiler Design

- Lexical analysis and parsing
- Syntax-directed translation
- Runtime environments
- Intermediate code generation
- Local optimization
- Data-flow analyses: constant propagation, liveness analysis, and common subexpression elimination

#### 8. Operating System

- System calls, processes, and threads
- Inter-process communication
- Concurrency and synchronization
- Deadlock
- CPU and I/O scheduling
- Memory management and virtual memory
- File systems

#### 9. Databases

- ER model
- Relational model, relational algebra, tuple calculus, and SQL
- Integrity constraints and normal forms
- File organization and indexing, including B and B+ trees
- Transactions and concurrency control

#### 10. Computer Networks

- Layering, OSI, and TCP/IP protocol stacks
- Packet, circuit, and virtual-circuit switching
- Data-link layer: framing, error detection, medium access control, and Ethernet bridging
- Routing: shortest path, flooding, distance vector, and link state
- Fragmentation, IP addressing, IPv4, and CIDR
- ARP, DHCP, ICMP, and NAT
- Transport layer: flow control, congestion control, UDP, TCP, and sockets
- Application protocols: DNS, SMTP, HTTP, FTP, and email

Sources: `IOCL-DOMAIN-SYL-2026`, page 7; `GATE-CS-SYL-2026`, pages 1–2.

## 4. Candidate baseline and priorities

The baseline is user-supplied from the personal CIL response record and is diagnostic context, not an IOCL exam pattern or an IOCL previous-year paper.

| Area | Baseline | Priority decision |
| --- | ---: | --- |
| General Awareness | 15/25 | Do not create an IOCL study track; the supplied IOCL 2026 pattern does not include General Awareness/GK |
| Numerical Ability | 12/25 | High priority, especially timed sets |
| Reasoning | 16/25 | Maintain with mixed practice |
| English | 17/25 | Maintain with short practice |
| CS Domain | 51/100 | High priority; start with Networks and Theory of Computation |

Some correct CIL responses were guesses. A correct answer must therefore not automatically count as mastery.

Initial study order:

1. Computer Networks
2. Theory of Computation
3. Timed Quantitative Aptitude
4. Other domain topics with low measured accuracy
5. Reasoning and English maintenance

The priorities become evidence-driven after enough in-app attempts exist; the baseline remains visible and is never overwritten by inferred data.

## 5. Required workflows

### 5.1 Today dashboard

- Show days remaining against the tentative date, with a visible tentative-date warning.
- Show the three current priorities.
- Resume an unfinished practice session when one exists.
- Show recent net score, accuracy, and confidence calibration without decorative charts.

### 5.2 Topic practice

- Choose section, subject, topic, question count, and timed or untimed mode.
- Support single-answer MCQs only in the first release because that is the notified IOCL format.
- Capture confidence (`guess`, `unsure`, or `confident`) before answer submission.
- Show the answer, explanation, provenance label, and exact source locator after submission or at session end.
- Allow flagging a question for review or reporting a content issue locally.

### 5.3 IOCL mock

- Reproduce 20 Quantitative Aptitude, 15 Logical Reasoning, 15 English, and 50 Domain questions.
- Enforce Section A before Section B, with independent 60- and 90-minute timers.
- Allow unanswered questions and review flags.
- Score `correct - 0.25 × incorrect`; unanswered is 0.
- Report section and overall qualifying thresholds separately from rank or selection. Never predict selection.
- Do not start a mock unless the approved bank contains enough eligible questions in every component.

### 5.4 Review

- Review incorrect answers, unanswered questions, and low-confidence correct answers.
- Use a four-way confidence view:
  - correct + confident: demonstrated knowledge;
  - correct + guess/unsure: fragile knowledge;
  - incorrect + confident: likely misconception;
  - incorrect + guess/unsure: known gap.
- Retry from the review list without changing the historical attempt.

### 5.5 Progress

- Show attempts, answered accuracy, IOCL net score, unanswered rate, and median or average response time by section/topic.
- Show accuracy by confidence level so guessed correctness is visible.
- Keep raw CIL baseline separate from IOCL-format practice results.

### 5.6 Local data control

- Store attempts, preferences, and current-session state in `localStorage` only.
- Provide explicit reset with confirmation.
- Provide JSON export/import before relying on the tool for long-term study history; validate imported data and never overwrite existing data without confirmation.

## 6. Content requirements

Every question record must include:

- stable ID;
- single-answer MCQ stem and options;
- correct option;
- explanation;
- section, subject, and topic from this specification;
- provenance label: `official`, `adapted`, or `original`;
- registered source ID and precise locator;
- explanation verification source(s);
- review status.

No question may appear in practice or mocks if its answer, explanation, source, or review status is missing. Detailed rules are in `docs/CONTENT_POLICY.md`.

Historical GATE content may be useful practice material, but it must never be called an IOCL previous-year question. GATE MSQ and NAT questions are excluded from IOCL-format mocks. The personal CIL response sheet supplies baseline context only and must not be copied into the question bank.

## 7. Technical scope

- React, Vite, and TypeScript
- Browser-only application
- `localStorage` persistence
- Static, repository-owned approved question data
- Responsive, keyboard-accessible interface
- No authentication, backend, cloud database, AI chatbot, telemetry, or network dependency for core practice
- No state-management, charting, date, or UI framework unless a demonstrated need survives implementation

One versioned localStorage document is sufficient initially. Migrations are added only when the stored schema actually changes.

## 8. Acceptance criteria for the first usable release

- The displayed exam pattern, timers, negative marking, qualification thresholds, syllabus, vacancy count, and tentative-date language match the cited official IOCL documents.
- A question cannot load without an explanation and registered provenance.
- A practice attempt records correctness, confidence, elapsed time, and net score independently.
- Low-confidence correct answers remain reviewable and do not appear as mastered solely because they were correct.
- An IOCL mock uses the exact 20/15/15/50 distribution, fixed section order, and 60/90-minute timing.
- Refreshing the page preserves a live session and completed history.
- Reset and import require confirmation; malformed imports do not damage stored data.
- The primary workflows are usable with keyboard only and on a phone-width viewport.
- No out-of-scope feature or unreviewed question is shipped.

## 9. Explicit non-goals

- Authentication or multiple users
- Backend, sync, cloud storage, or collaboration
- AI-generated questions or chatbot tutoring
- Social features, leaderboards, gamification, or portfolio-style animation
- General Awareness preparation, unless a later official IOCL correction adds it
- Rank, cutoff, or selection prediction
- Scraping or reproducing paid/copyrighted test-series material
- A generic GATE preparation platform
